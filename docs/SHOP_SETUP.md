# 온라인 구매 설정 가이드 (표준품·소켓)

국문 홈페이지의 **티타늄 주름관 표준품**과 **주름관 소켓**을 카드로 바로 살 수 있게 하는 기능입니다.
맞춤 열교환기·폐열회수기·대량 주문은 지금처럼 견적 문의로 받습니다.
구조는 같은 회사의 반지몰(tauti)에서 검증된 결제·재고 흐름을 옮겨 왔습니다.

아래 순서대로 한 번만 설정하면 됩니다. **판매를 켜기 전에 맨 아래 「판매 전 확인」을 꼭 끝내세요.**

## 1. Supabase 새 프로젝트 (주름관 전용)

1. supabase.com → New project — **Region: Northeast Asia (Seoul)** 로 만듭니다
   (개인정보처리방침에 「데이터는 서울 리전에 저장」이라고 적어 두었습니다).
2. SQL Editor 에 `supabase/migrations/002_shop.sql` 전체를 붙여넣고 실행합니다. 여러 번 실행해도 안전합니다.
   - `shop_items`(판매 품목: SKU 별 가격·재고), `orders`·`order_items`(주문), 재고 함수가 만들어집니다.
   - 표준품 3종·소켓 4종이 **가격 0원·재고 0·판매 중지** 상태로 들어갑니다.
3. Project Settings → API 에서 `Project URL` 과 `service_role` 키를 복사해 둡니다(다음 단계 환경변수).

> 예전 관리자 화면이 쓰던 Supabase 프로젝트(products·inventory·orders 표)는 더 이상 쓰지 않습니다.

## 2. 환경변수 (Vercel → Project → Settings → Environment Variables)

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | 1단계 새 프로젝트의 Project URL (예전 값이 있으면 **새 값으로 교체**) |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | 새 프로젝트의 service_role 키 (서버에서만 씀) |
| `NEXT_PUBLIC_PORTONE_STORE_ID` | ✅ | 포트원 상점 ID |
| `NEXT_PUBLIC_PORTONE_CHANNEL_KEY` | ✅ | 포트원 채널 키 — 처음엔 테스트 채널, PG 계약 후 실연동 채널로 교체 |
| `PORTONE_API_SECRET` | ✅ | 포트원 V2 API Secret (결제 확인·환불) |
| `PORTONE_WEBHOOK_SECRET` | 권장 | 포트원 웹훅 시크릿(`whsec_…`) |
| `ADMIN_PASSWORD` | ✅ | 관리자(/admin) 비밀번호 |
| `ADMIN_SESSION_SECRET` | ✅ | 16자 이상 임의 문자열 (예: `openssl rand -hex 32`). 예전 값을 그대로 써도 되지만 16자 이상이어야 함 |
| `SMTP_USER`, `SMTP_PASS` | 기존 | 견적 메일과 같은 Gmail — 주문 확인·출고·취소 메일도 이 계정으로 보냄 |
| `ADMIN_NOTIFY_EMAIL` | 선택 | 새 주문 알림 받을 주소 (없으면 777@atx.kr) |

더 이상 쓰지 않는 값: `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `ANTHROPIC_API_KEY` (예전 관리자 화면용). 지워도 됩니다.

`NEXT_PUBLIC_*` 값은 빌드할 때 들어가므로 바꾼 뒤 **다시 배포**해야 반영됩니다.

## 3. 포트원 콘솔

1. portone.io 가입 → 상점 ID 확인 → **테스트 채널**을 하나 만들어 채널 키를 받습니다(계약 전에도 가능).
2. 결제 연동 → 연동 정보 → **웹훅**: URL `https://tube.atx.kr/api/payment/webhook` 등록 → 시크릿을 `PORTONE_WEBHOOK_SECRET` 에.
   구매자가 결제 직후 창을 닫아도 웹훅으로 결제완료 처리됩니다.
3. 테스트 채널로 결제 → 관리자에서 발송 처리 → 취소·환불까지 한 번 해 본 뒤, PG 계약이 끝나면 실연동 채널 키로 바꿉니다.
4. 결제 수단은 카드(`CARD`)입니다. PG 결제창에 간편결제가 함께 뜨는 경우가 많습니다.

## 4. 판매 품목 입력

관리자(`/admin`) → **판매 품목·재고**

- 품목마다 **판매가(부가세 포함)** 와 **재고**를 넣고 「판매 중」을 켠 뒤 저장합니다. 0원이면 켤 수 없습니다.
- 저장하면 제품 페이지(`/products/tube-standard`, `/products/socket`)에 구매 상자가 바로 나타납니다.
- 다른 길이·피팅을 팔려면 아래 「새 판매 품목 추가」로 SKU 를 만들면 됩니다.
- 재고가 0이면 「품절」로 보이고 견적 문의로 안내합니다.

## 5. 판매 전 확인 (법적 표시·정책)

| 항목 | 고칠 곳 | 상태 |
| --- | --- | --- |
| 대표자 이름 | `src/lib/shop/config.ts` → `SELLER.representative` | ⬜ 비어 있음 |
| 통신판매업 신고번호 | `SELLER.mailOrderNo` (신고 전이면 관할 구청에 신고) | ⬜ 비어 있음 |
| 배송비 4,000원 · 10만 원 이상 무료 (임시값) | `SHIPPING_FEE`, `FREE_SHIPPING_THRESHOLD` | ⬜ 회사 확인 |
| 교환·반품 조건(7일, 가공품 제외, 단순 변심 왕복 배송비) | 이용약관 제6조 `src/components/legal/terms-content.ts`, 안내 `ShopPolicyNotice.tsx` | ⬜ 회사 확인 |
| 결제대행사(PG) 이름 | 개인정보처리방침 위탁 표 「포트원과 연동된 결제대행사」 → 실제 PG 사명 | ⬜ 계약 후 |
| 약관·방침 시행일 2026-11-12 | 이 날짜 이후 판매 시작(또는 날짜 조정 후 7일 공지) | ⬜ |
| 테스트 결제 → 발송 → 환불 한 번 | 3단계 | ⬜ |

대표자·신고번호를 채우면 푸터에 자동으로 표시됩니다(비어 있으면 그 항목만 숨김).

## 운영 흐름

1. 구매자 결제 → 주문이 **결제완료**, 재고 자동 차감, 구매자·관리자에게 메일
2. 관리자 → **주문 관리 › 처리할 주문**에서 택배사·송장번호 입력 → **발송 처리** → 배송중 + 출고 메일
3. 필요하면 **배송완료**로 표시
4. 취소 요청 → **주문 취소·환불**: 포트원으로 전액 환불하고, 고르면 재고를 되돌립니다

참고
- 결제창을 연 주문은 30분 동안 재고를 잡아 둡니다. 결제하지 않으면 자동으로 풀립니다.
- 금액은 항상 서버가 DB 가격으로 계산하고, 결제 뒤 포트원에서 실제 금액을 다시 조회해 대조합니다. 다르거나 재고가 없으면 자동 전액 취소합니다.
- 같은 접속자(IP)는 결제 대기 주문 2건, 대기 수량 100개, 1시간에 주문 10건까지만 만들 수 있습니다(재고 묶어 두기 방지). 한 품목은 최대 50개 — 더 많으면 견적 문의로 안내합니다. 값은 `src/lib/shop/config.ts`.
- IP 는 저장하지 않고 서버 비밀키로 해시한 값만 저장합니다. 결제가 끝나지 않은 주문은 1년 뒤 자동으로 지워집니다.
- 구매자는 **주문 조회**(`/orders`)에서 주문번호 + 휴대폰 번호로 상태와 송장을 확인합니다.
- 부분 환불은 지원하지 않습니다. 필요하면 포트원 콘솔에서 직접 처리하세요.
- **세금계산서**: 카드 결제는 카드 매출전표가 증빙이라 같은 거래에 세금계산서를 따로 발행하지 않습니다. 세금계산서가 필요한 손님은 견적 문의(계좌이체)로 받습니다.
